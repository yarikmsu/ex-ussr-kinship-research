# Дополнения форка

Форк дополняет навык уроками из исследований его владельца. Основной текст навыка (`SKILL.md`, `references/*.md`) совпадает с каноническим репозиторием — кроме раздела «Дополнения форка» в `SKILL.md`. Дополнения лежат в этой папке, кейсы — в `evals/fork-lessons.yaml`. Поэтому слияние обновлений почти не даёт конфликтов.

## Как читать

- `references/fork/<имя>.md` дополняет одноимённый `references/<имя>.md`. Заголовки разделов повторяют заголовки основного файла с пометкой «— дополнения форка».
- `techniques.md` (если есть) — технические приёмы работы с браузером, просмотрщиками и сервисами.
- `evals/fork-lessons.yaml` — кейсы для содержательной проверки дополнений. Это не автоматические тесты.
- `scripts/upsert_register.py` и его тесты — строгое обновление реестров дела из JSON. Это единственный скрипт форка.

## Приоритет

Правила форка определяет его владелец. При расхождении с основным текстом действует текст форка.

## Публичность

Репозиторий публичный. Примеры обобщены: в них нет имён, мест, дат и идентификаторов конкретных дел. Материалы дел хранятся вне этой рабочей копии.

## Обновление из канонического репозитория

Здесь `origin` — этот форк, `upstream` — канонический репозиторий; проверьте `git remote -v`. В копии, клонированной из форка, `upstream` добавляется один раз:

```bash
git remote add upstream https://github.com/DenisSergeevitch/ex-ussr-kinship-research.git
```

Обновление из форка: `git pull --ff-only`.

Чтобы влить изменения канонического репозитория, после `git fetch` и перед `git merge upstream/main` просмотрите их (`git log -p main..upstream/main`). Особенно внимательно — новый исполняемый код: импорты, сетевые и записывающие вызовы.

```bash
git fetch origin && git fetch upstream
git switch main
git merge --ff-only origin/main
git merge-tree --write-tree --name-only main upstream/main   # конфликты без касания рабочей копии
git diff $(git merge-base main upstream/main) upstream/main -- SKILL.md references/ evals/   # что изменилось в основном тексте
git merge upstream/main
python3 -m unittest discover -s tests
```

Ветку форка не перезаписывать: без `--force` и без `gh repo sync --force`.

После каждого слияния сверьте дополнения с новым основным текстом. Дополнение важнее основного текста, поэтому узкая формулировка форка может перекрыть более точную, принятую в каноническом репозитории.

1. Сверяйте только изменения основного текста с прошлого слияния: их показывает `git diff` из блока выше, если выполнить его до `git merge`. После слияния тот же список даёт `git diff <слияние>^1...<слияние>^2 -- SKILL.md references/ evals/`, где `<слияние>` — коммит слияния: на следующих коммитах `HEAD^2` уже нет.
2. По каждому пересечению с дополнением выберите одно:
   - основной текст покрывает дополнение полностью — удалить дополнение;
   - основной текст точнее в части — перенести эту часть в дополнение;
   - дополнение сильнее — оставить его и сослаться на основной текст.
3. Спорный выбор решайте кейсом из `evals/fork-lessons.yaml`. Если с формулировкой основного текста агент снова делает ошибку, которую кейс ловил без дополнения, дополнение остаётся.
4. `git push origin main` — только после сверки и с согласия пользователя: иначе форк опубликует дополнения, которые перекрывают более новый основной текст.

## Перенос в канонический репозиторий

Отдельные дополнения предлагаются в канонический репозиторий отдельными PR — в обобщённой форме и по его правилам. Если принятый текст полностью покрывает дополнение, дополнение отсюда удаляется. Если дополнение остаётся сильнее, его сохраняют.
